# Library Management System — Backend

REST API for a multi-branch library management system, built as my bachelor's thesis at the Zagreb University of Applied Sciences (TVZ), 2025.

It covers the full lifecycle of a library network: the book catalogue, copies available at each branch, memberships, reservations, loans and invoices. It serves four user roles, each with its own permissions.

**Frontend:** [LibraryFrontend](https://github.com/IvanSustic/LibraryFrontend) (Angular 19)

## Tech stack

| Area | Technology |
| --- | --- |
| Language | Java 21 |
| Framework | Spring Boot 3.4 (Web, Data JPA, Validation, Mail) |
| Security | Spring Security, JWT access and refresh tokens (jjwt) |
| Database | MySQL, schema generated by Hibernate |
| Build | Maven (wrapper included) |
| Other | Lombok, scheduled jobs (`@Scheduled`), multipart image uploads |

## Features

- **Authentication:** separate login flows for members and staff. Sessions use short-lived JWT access tokens with refresh tokens stored server-side, and the API supports logout.
- **Password reset by email:** a member requests a reset link, which is delivered through SMTP and leads to a token-protected reset form.
- **Role-based access control:** every endpoint is restricted to the roles that need it (see below).
- **Catalogue management:** books, authors, genres and book types, with cover image uploads.
- **Multi-branch inventory:** each library branch tracks how many copies of each book it holds.
- **Memberships:** staff enrol members at a branch. Memberships expire, and a loan requires an active membership.
- **Reservations:** members reserve a book for two weeks, and staff turn a reservation into a loan when it is picked up.
- **Loans:** two-week loans, returns, and a separate flow for books returned damaged.
- **Invoices:** generated for memberships and damages.
- **Nightly clean-up job:** runs at 02:00. It removes expired reservations, reservations held by members whose membership lapsed, and expired memberships with no open loans.

## Roles

| Role | What they can do |
| --- | --- |
| Member (`ROLE_USER`) | Browse the catalogue, reserve books, view their own loans, reservations and memberships |
| Librarian (`Knjižničar`) | Enrol members, issue and close loans, handle reservations and damaged returns |
| Branch manager (`Voditelj knjižnice`) | Everything a librarian can do, plus manage the catalogue, branch inventory, staff and invoices |
| Admin | Manage branches, locations, members and all staff |

## Architecture

The code follows a standard layered Spring structure:

```
src/main/java/org/library
├── controller/   REST endpoints
├── service/      business logic (interface + implementation)
├── repository/   Spring Data JPA repositories
├── model/        JPA entities
├── dto/          request and response objects
├── configs/      security and CORS configuration
├── filter/       JWT authentication filter
├── utils/        JWT helper
└── tasks/        scheduled clean-up job
```

The domain is modelled in Croatian, the language of the thesis. The main entities are:

| Entity | Meaning |
| --- | --- |
| `Knjiga` | Book |
| `Autor` | Author |
| `Zanr` | Genre |
| `TipKnjige` | Book type |
| `Knjiznica` | Library branch |
| `KnjiznicaImaKnjige` | Copies of a book held at a branch |
| `Korisnik` | Member |
| `Zaposlenik` | Staff member |
| `RadnoMjesto` | Staff role |
| `Clanstvo` | Membership |
| `Rezervacija` | Reservation |
| `Posudba` | Loan |
| `Racun` | Invoice |
| `TipRacuna` | Invoice type |
| `Mjesto` | City or location |

## API overview

| Resource | Base path | Purpose |
| --- | --- | --- |
| Auth | `/auth` | Login, registration, token refresh, logout and password reset |
| Books | `/api/knjige` | Catalogue CRUD |
| Authors, genres, book types | `/api/autor`, `/api/zanr`, `/api/tipKnjige` | Catalogue reference data |
| Branches | `/api/knjiznica` | Branches and the copies each one holds |
| Memberships | `/api/clanstvo` | Enrolment and membership lookup |
| Reservations | `/api/rezervacije` | Reserve a book and convert a reservation to a loan |
| Loans | `/api/posudba` | Issue, return and mark a loan damaged |
| Invoices | `/api/racun` | Invoice overview |
| Members and staff | `/api/korisnik`, `/api/zaposlenici` | Account management |
| Images | `/api/slika` | Book cover and branch image uploads |

## Getting started

### Prerequisites

- Java 21
- MySQL 8
- An SMTP account for password-reset emails, such as a Gmail app password

### 1. Create the database

```sql
CREATE DATABASE knjiznica;
```

Hibernate creates and updates the tables on startup (`ddl-auto=update`).

### 2. Configure

Edit `src/main/resources/application.properties`, or override the values with environment variables:

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/knjiznica
spring.datasource.username=<db user>
spring.datasource.password=<db password>

security.jwt.secret-key=<64-character hex secret>
security.jwt.expiration-time=3600000

spring.mail.username=<smtp user>
spring.mail.password=<smtp app password>

file.upload-dir=../images
```

### 3. Run

```bash
./mvnw spring-boot:run
```

The API starts on `http://localhost:8080`. CORS is configured for the Angular frontend at `http://localhost:4200`.
